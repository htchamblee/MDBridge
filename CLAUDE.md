# MDBridge: rules for contributors (people and agents)

- **Improve, don't copy bugs.** MDATK v0.0.4.1 (and MDAnalysis behind it) is the reference for
  behaviour, but where it has a bug, a crash, a misleading message or a numerically fragile
  result, MDBridge fixes it. Record each fix in `docs/DIFFERENCES.md` (what, why, how tested) and
  make the parity tests expect the improved behaviour. Conventions users rely on (file formats,
  names, options, output layout) stay as MDATK has them. See "Definition of done" in
  `docs/ARCHITECTURE.md`.
- **Clean room for MDAnalysis (LGPL).** Never copy or translate MDAnalysis code. Spec writers
  read and run it and write behaviour-only specs in `docs/specs/`; implementers of that behaviour
  never open MDAnalysis or the code a rewrite replaces (`docs/specs/README.md`, `LICENSING.md`).
  MDATK's own code (same owner) may be ported freely; permissive ports carry their notices.
- **Data tables** (residues, elements, masses, ions) come from the independent sources in
  `data/sources/`, never from MDAnalysis.
- **Supported compilers:** GCC 11+ and MSVC 2022 (`/W4`, warnings as errors); not Clang.
- **Test data** is generated by `tests/parity/` generators and must be reproducible:
  `tests/parity/regenerate_all.py` (CI runs it). Never edit generated files by hand.

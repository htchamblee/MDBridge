# Improvement register: inherited MDATK v0.0.4.1 / MDAnalysis 2.11.0 bugs and quirks

Planned fixes; each one moves to `docs/DIFFERENCES.md` when it is done.

Audit of 7013a89. It applies the rule in CLAUDE.md and in
"Definition of done" (docs/ARCHITECTURE.md): bugs, crashes, misleading messages and numerically fragile
results get fixed. Conventions users rely on stay.

Sources: docs/specs/*.md, tests/data/README.md, the generators' docstrings (tests/parity/*.py),
comments in the MDBridge sources, the committed test data (cli_cases.json, io/loader/topology_cases.json,
io/trajectories/cases.json, analysis/systems_cases.json), and MDATK v0.0.4.1 (/home/user/htchamblee/mdatk:
mdatk/spatial.py, mdatk/analysis/*.py, mdatk/selections.py, mdatk/io/loader.py, mdatk/config.py).
Everything below describes behaviour only. It contains no MDAnalysis code.

Columns: **Current** is what MDBridge does now, which is the same as MDATK/MDAnalysis unless stated.
**Why** says why this is a bug or a convention. **Proposal** is the improved behaviour, precise enough to
test. **Impact** says which outputs change. "Parity data" means the expected values in tests/data or the
tests must be adjusted on the test side, as `tests/parity/independent_tables.py` does. **Effort** is
S/M/L. **Rec.** is FIX, KEEP or ASK.

Labels used throughout:
- "Python-text error": an error whose text is a Python/numpy internal message with no file, line or field
  (e.g. `list index out of range`, `'NoneType' object ...`, an empty message).
- "**Reader-message rule (RM)**": the error names the file, the line or record number when one is known,
  and the field, and says what was expected. This applies to every reader fix marked "RM". The exception
  class seen through `pythonName()` may change to ValueError/OSError. The CLI prints `error: <message>`
  and exits with 1.
